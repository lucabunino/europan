# Migrate to paraglide-js v2, drop @inlang/paraglide-sveltekit; explicit href localization

Follow-up to ADR-0002, where this was deferred. `@inlang/paraglide-sveltekit` is deprecated outright by its own maintainers ("use paraglide-js directly with v2 or above") and hard-pins an internal v1 copy of `@inlang/paraglide-js`, so there was no partial/incremental path — the whole i18n wiring (`vite.config.js`, `hooks.server.js`, `+layout.svelte`, the language switcher) had to move to v2's native SvelteKit integration in one pass.

**German URLs now get an explicit `/de` prefix** in front of the existing translated words (`/de/wettbewerb` instead of `/wettbewerb`) — a deliberate scheme change decided mid-migration, not a carryover from v1. French (base locale) stays unprefixed. To avoid hand-repeating the prefix across ~20 route entries, `vite.config.js` declares each route once as `{pattern, fr, de}` and maps it into paraglide's `urlPatterns` tuples, prepending `/de` programmatically.

**Bigger architectural finding**: v1's `<ParaglideJS>` wrapper component silently auto-localized every internal `href="/..."` site-wide via client-side link interception — this is *why* the entire codebase could get away with writing plain canonical hrefs (`href="/competitions"`) everywhere and still show translated URLs (`/wettbewerb`) after navigation. v2 has no equivalent mechanism; paraglide's own docs only demonstrate wrapping individual language-switcher links, not a codebase-wide solution. Two options existed: a single global click-interceptor replicating the old wrapper's behavior in one place, or explicitly wrapping every internal href with `localizeHref()` at the call site. Chose the explicit-wrapping approach (paraglide's own documented pattern) over reintroducing implicit global link-rewriting — more files touched, but no invisible cross-cutting behavior for a future reader to rediscover.

Verified via `npm run build` plus `curl` across every route in both languages (including dynamic slugs, the language switcher, and the first-visit `accept-language` redirect) — a full visual click-through remains the user's responsibility before merging `deps/frontend-major-upgrade` into `stage`.
